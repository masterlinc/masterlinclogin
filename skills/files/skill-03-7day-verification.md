## 场景痛点

很多管理者「用 AI 一周」后说不清到底省没省时间：感觉忙，但没有数字。**没有记录，就没有「验证」，只有「感觉」。** 7 天验证表解决的就是「AI 到底有没有真的减负」——用 7 天的连续记录换一个能拍板的答案。

## 核心方法：连续 7 天，每天只填三格

### 第一步：定目标（第 1 天做一次）

把自检/行动卡定好的那件事写下来，并写下可验证的目标：

> 这一周，我的唯一动作是：________
> 目标：从 ____ 分钟 → ____ 分钟　｜　出错 ____ 次 → ____ 次

### 第二步：每天 3 分钟，只填三格

| 天 | 今天做了什么（30 字内） | 卡在哪（1 句） | 下一步（1 句） |
|---|---|---|---|
| 第 1 天 | | | |
| 第 2 天 | | | |
| 第 3 天 | | | |
| 第 4 天 | | | |
| 第 5 天 | | | |
| 第 6 天 | | | |
| 第 7 天 | | | |

中断一天不算失败——从那天接着填，别从头再来。

### 第三步：第 7 天收尾（2 分钟）

- 实际耗时：从 ____ 分钟 → ____ 分钟
- 出错次数：____ 次（可接受吗：是 / 否）
- 这件事值不值得继续：值得 / 不值得 / 换个做法
- 下一周动作：________

## 三条说明

1. **「卡在哪」比「做了什么」重要**——卡点就是下一周要解决的题，别藏。
2. **第 7 天不达标不丢人**——记录本身就是收获。连续两次不达标，再回头改行动卡上的「输入 / 审核 / 返工点」。
3. **这张表只负责「跟踪」，不负责「方法」**——把这件事真正做对、做稳，需要完整方法论。

## 管理判断点

- **目标定多少算「成功」**：从 N 分钟到几分钟、出错几次以内，只有你知道可接受线，AI 帮不了。
- **卡点值不值得继续投入**：第 7 天的「值得 / 不值得 / 换个做法」是个判断，不是数据结论。
- 连续两次不达标时，要回去改「输入 / 审核 / 返工点」——那是方法层的事，不是记录层的事。
