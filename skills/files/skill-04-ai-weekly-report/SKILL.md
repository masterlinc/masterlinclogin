# AI 写周报法

## 功能说明

本技能把用户的随手记素材（周一到周五记的关键词）整理成一份四段周报初稿：**① 本周完成 ② 本周判断/决定 ③ 下周计划 ④ 需要老板知道的 1 件事**。

周报的难点从来不是「写」，是「记」。AI 再强，也写不出用户没干过的事——AI 做信息搬运（分类、压缩、换说法、查漏），用户做三件事：定结论、定承诺、定「要老板知道的」。

## 核心分工（AI 替不了的部分）

- **AI 做**：把素材分类压缩、把「做了事」升级成「决定了什么 / 推动了什么」、按四段排版；
- **用户做（必须提醒）**：结论（本周最重要的一件事）、下周承诺、需要老板拍板/资源/知晓的一件事。

## 输出格式（普通周报 · 每周用）

```
① 本周完成
- 【每条 30 字内，数字优先】

② 本周判断/决定
- 【这周真正重要的决定】

③ 下周计划
- 【可验证的动作 + 时间，不写「持续推进」「加快进度」】

④ 需要老板知道的 1 件事
- 【需要拍板 / 需要资源 / 需要知晓，只写一件】
```

## 生成规则（必须遵守）

1. 每条 30 字内；
2. 把「做了事」升级成「决定了什么 / 推动了什么」，不要停留在「参与了 / 处理了」；
3. **不确定的不要编，标「待补充」**——用户没记的素材，AI 不可能知道；
4. 「下周计划」写成可验证的动作 + 时间，不写「持续推进」「加快进度」这类空话；
5. 数字优先：有数字的写数字，没数字的用「从…到…」结构；
6. 事实错误宁可标「待确认」，不猜测。

## 三套变体（根据场合选择）

同一套素材，换一个目的，就是另一篇东西。判断标准：

| 场合 | 用哪套 | 判断标准 |
|---|---|---|
| 每周例行 | 变体 1 普通周报 | 上级只看进展，不问绩效细节 |
| 季度/晋升/评审 | 变体 2 述职周报 | 听众不了解日常，只看影响与结果 |
| 专项汇报/要资源 | 变体 3 汇报材料 | 有明确建议或请求，要老板拍板 |

### 变体 2 · 述职周报（季度/晋升用）

按三段生成：① 我负责什么（职责边界，30 字内）② 我做出了什么结果（数字和前后对比，每条 40 字内）③ 我沉淀了什么方法/带出了什么团队（具体到可复用的流程或人的成长）。

要求：
- 只写「我推动的结果」，不写「我参与的过程」；
- 每个结果必须配数字或对比（如「从 3 天缩短到 1 天」「新增 2 条可复用 SOP」）；
- 没有数字的地方标「待补充」，不用「显著提升」「大幅优化」这类没法验证的词；
- 语气是从容的陈述，不是自我表扬。

### 变体 3 · 汇报材料（向上汇报/要资源用）

按四段生成：① 结论（一句话：建议什么 / 要什么资源）② 依据（3 条以内，每条带数字）③ 风险与前提（什么情况下结论不成立）④ 需要老板拍板的点（只列 1-2 个，每个给「建议 + 备选方案」）。

要求：
- 结论必须在第一句，不许铺垫；
- 老板只看 3 分钟，全文控制在 300 字内；
- 把「我觉得应该」改成「基于数据，建议」；
- 标出 1 个拿不准、需要老板判断的点——这比显得全知更有价值。

## 使用注意事项

- 只基于用户提供的素材写作，用户没写的工作不要脑补；
- 生成初稿后提醒用户：**先别改文字，先看结构**——哪些事没记（AI 不可能知道）、哪条事实错了（AI 可能猜错），把缺的补上、错的划掉；
- 提醒用户「人只改判断」：结论、下周承诺、要老板知道的，三处以外的句子不值得浪费时间润色；
- 涉及人名、金额、内部决策：提示先脱敏或用最小样本。
